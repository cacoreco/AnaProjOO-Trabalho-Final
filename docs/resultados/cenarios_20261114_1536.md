## Conceitual
**Pergunta:** Explique o que é o padrão Memento e qual problema ele resolve.

**Resposta (357s):**

O padrão Memento resolve o problema de capturar e externalizar o estado interno de um objeto para que possa ser restaurado depois, sem violar o encapsulamento. Os três participantes são: o Originator (que tem acesso total ao seu estado), o Memento (que guarda o snapshot do estado) e o Caretaker (que guarda e devolve mementos).

O Memento é opaco para o Caretaker, ou seja, o Caretaker só tem acesso a métodos de salvar e recuperar mementos. O Memento não tem métodos públicos de leitura. O Originator é o único que lê o conteúdo do Memento.

No exemplo de Editor de texto, o Editor (Originator) salva o estado atual do texto em um Memento. O Memento guarda uma cópia do texto. O Caretaker (Histórico) guarda e devolve mementos. Quando o Editor precisa restaurar o estado anterior, ele usa o Memento recuperado pelo Caretaker para restaurar o texto. Nesse processo, o Memento não lê o conteúdo do Editor, mantendo o encapsulamento.

## Seleção
**Pergunta:** Descreva uma situação em que o padrão Memento é a melhor escolha e uma em que ele deveria ser evitado, explicando o porquê.

**Resposta (111s):**

Em uma situação onde é necessário salvar e restaurar o estado de um editor de texto sem violar o encapsulamento, o Memento é a melhor escolha. Por exemplo, em um editor de texto que permite desfazer ações, como apagar uma palavra ou mover o cursor, o Memento pode salvar o estado do editor antes da ação e restaurar esse estado quando o usuário desejar desfazer a ação.

No entanto, o Memento deveria ser evitado em uma situação onde o estado do editor é muito grande ou mudar-se-ia frequentemente. Por exemplo, se o editor de texto tivesse que salvar o texto inteiro do arquivo em cada tecla digitada, isso seria muito custoso em termos de memória. Nesse caso, seria melhor usar o padrão Command, que apenas guarda a operação e a inversa, em vez de salvar o estado completo.

## Conceitos equivocados
**Pergunta:** Com qual padrão o Memento é mais confundido? Explique a diferença entre eles e por que essa confusão acontece.

**Resposta (112s):**

O padrão Memento é mais confundido com o padrão Command. A principal diferença entre eles é que:

- **Memento**: Captura e salva o estado interno de um objeto para que possa ser restaurado em um ponto posterior. O Memento é opaco para o Caretaker, que apenas guarda e devolve mementos. O Originator lê o conteúdo do Memento para restaurar seu estado.

- **Command**: Guarda uma operação e sua inversão (ou inversão possível). O Command é usado para desfazer uma operação específica, onde o Memento salva o estado antes da operação.

A confusão acontece porque ambos são usados para implementar a funcionalidade de desfazer (undo), mas o Memento salva o estado, enquanto o Command salva a operação e sua inversão.

**Exemplo de uso do Memento**:
- **Editor de Texto com Desfazer**: O Editor de Texto mantém o estado interno do texto. Quando o usuário faz um desfazer, o Memento captura o estado atual do texto e o restaura, preservando o encapsulamento.

**Exemplo de uso do Command**:
- **Comando de Operação**: Quando um usuário executa uma operação, como "converter para maiúsculas", o Command salva a operação e sua inversão (converter para minúsculas). O Command permite desfazer a operação específica, sem precisar salvar o estado do Editor de Texto.

O Caretaker (Historico) não tem métodos para ler, salvar ou restaurar o conteúdo do Memento; ele apenas guarda e recupera mementos.

O Editor (Originator) é o único que lê o conteúdo do Memento. Ao salvar, o Editor cria um novo Memento (EstadoEditor) que copia o estado atual do Editor. Ao restaurar, o Editor usa o conteúdo do Memento para restaurar seu estado para o estado armazenado no Memento. O Editor não precisa acessar diretamente o estado do Memento, pois o Memento é opaco para o Caretaker.
